Direct-stream 4K from TorBox into PotPlayer.

Jellyfin library + TorBox cloud + PotPlayer playback, on Windows, with no transcoding. Cloud torrents mount as local drives, Jellyfin keeps metadata, resume and Next-Up, and PotPlayer direct-streams full-season 4K through a local proxy. A loopback-only panel owns start/stop, health and Play-in-PotPlayer.

Features

Everything between the cloud and the couch.

Six moving parts, one chain. Each one is a script or service in the repo, so you can read exactly what runs.

TorBox proxy

Stable local URLs that never expire. It refreshes short-lived CDN links per request and caches mylist to stay fast.

server/torbox-proxy.py · :8888

One-click play

Jellyfin Play hands a potplayer:// link to Windows. The launcher picks the right file, refreshes stale cache and opens the full season at your resume point.

potplayer-launcher.ps1 · bridge :18099

Resume sync

Posts progress every 5 s and marks Played at 80%, so Next-Up keeps working on every client.

potplayer-sync-tracker.ps1

Watch console

A live tail of launcher and playback ticks, episode hints and 80% Played events.

show-playback-log.ps1

Control panel

Loopback-only Start / Stop / Restart, status, metrics and Play buttons. No console juggling.

Ordered start (mounts, proxy, bridge, Jellyfin, panel) plus a watchdog, mutex and PID files.

Press play

One click, end to end.

This is the repo's own walkthrough of a single episode, from the panel to the progress bar and back to Jellyfin.

# the whole loop, in your browser
http://127.0.0.1:18080   # Start all
http://127.0.0.1:8096    # Jellyfin: Play-in-PotPlayer

  1. Start everything

    Open the panel and click Start all. Mounts come first, then proxy :8888, bridge :18099, Jellyfin :8096 and the panel itself.

  2. Pick a show in Jellyfin

    Metadata, posters and Next-Up come from TMDB plus the .strm scan.

  3. Press Play-in-PotPlayer

    A potplayer:// link is built and handed to Windows.

  4. Launcher resolves

    It maps the Jellyfin item to a .strm on T:\, refreshes a stale VFS through rclone RC :5572 if needed, and picks the TorBox CDN or the :8888 proxy fallback.

  5. PotPlayer opens the season

    A full-season UTF-16 .dpl loads with your episode queued and /seek= set to your Jellyfin resume position.

  6. Watch the bar fill

    Direct HTTP from :8888/torbox/... 302s to a fresh CDN URL, so 4K REMUX direct-streams with a full-cache seek bar.

  7. Resume stays in sync

    Progress is POSTed every 5 s and the episode is marked Played at 80%. Pause in Jellyfin Web, resume in PotPlayer, and Next-Up advances.

How it works

One required chain, supervised end to end.

Every play follows the same path. The proxy hides expiring CDN links behind stable loopback URLs; the sync tracker closes the loop back to Jellyfin.

Proxy leg

Hides expiring CDN tokens behind stable loopback URLs. Only the short resolver result is cached; expiry becomes a redirect.

Bridge leg

Exposes /health and /status and refuses to start unless the proxy is healthy. The supervisor and panel enforce the same gate.

Panel leg

Merges live process scans with proxy /metrics, and runs bulk Start / Restart in mount-first order with health waits. Stop reverses it.

Full service map, session model and boot order: ARCHITECTURE.md. Day-2 operations: RUNBOOK.md.

Quick start

Installed in about 30 seconds.

For a fresh PC with the prerequisites already installed: PotPlayer x64, rclone + WinFsp, Python 3.11, Jellyfin 10.x files and a TorBox account. Pick one path.

git clone https://github.com/MHJoy99/jellyfin-torbox-potplayer-stack.git
cd jellyfin-torbox-potplayer-stack
pwsh -File install.ps1 -WhatIf
pwsh -File install.ps1

install.ps1 prompts for TORBOX_API_KEY (masked), validates it with a live API call, initializes the F:\Jellyfin directory layout, registers the potplayer:// protocol handler and the MediaStackSupervisor scheduled task, starts the stack and runs port health probes (:8888, :18099, :18080, :8096). Switches (-WhatIf, -Uninstall, -SkipTasks, -Portable, -TorboxApiKey, -KeyScope) are in docs/install.md.

pwsh -File setup-wizard.ps1

Step-by-step: masked key entry, library root folders, Jellyfin connection test, PotPlayer auto-detection, rclone configuration, port availability and playback mode, with a dry-run preview before anything is applied. Supports -Resume and -NonInteractive.

# Run component installers in dependency order:
pwsh -File install-all.ps1

# Perform one-time ordered service startup (mounts -> proxy -> bridge -> Jellyfin -> panel):
pwsh -File supervisor.ps1 -Mode Start

Full dependency order and verification steps live in docs/install.md and docs/quickstart.md.

Then open the panel

http://127.0.0.1:18080

Click Start all, wait for green, open Jellyfin at http://127.0.0.1:8096, press Play-in-PotPlayer. The full-season playlist opens at your resume point.

Performance notes

Pre-tuned for high-bitrate 4K.

Defaults aimed at residential gigabit connections, taken from the repo's mount script and proxy.

rclone VFS mount

--vfs-cache-mode full with a 25G cache cap, 12h max age and 30G min free space. Chunks start at 32M (fast first byte) and double to 256M with 128M read-ahead. Directory cache 15m. Keep the cache on an NVMe SSD.

mount-torbox.ps1

Local proxy

Fresh CDN links by 302 with a token-bucket rate limiter, a shared mylist cache (10 minutes, singleflight coalescing) and HTTP/1.0 progressive streaming to avoid client hangs.

server/torbox-proxy.py

Seek bar & prefetch

PotPlayer gets progressive HTTP straight from the proxy for instant seeking. Set $env:FULLCACHE = "1" before launch to cache the full file for ultra-high-bitrate REMUX.

~20 GB disk headroom suggested

FAQ

Questions, answered from the repo.

What does this stack do that plain Jellyfin cannot do on Windows?

It mounts TorBox and Google Drive as local drives with rclone, serves fresh CDN URLs through a local proxy on port 8888, and launches PotPlayer with a full-season playlist at your exact resume point. Jellyfin keeps the library, metadata and watched state, while PotPlayer handles 4K direct-stream playback without transcoding or browser codec limits.

Where do I store my TorBox API key so it never leaks to GitHub?

Store it only as a Windows environment variable named TORBOX_API_KEY at User or Machine scope, then restart the proxy and supervisor so child processes inherit it. Never paste the key into scripts, configs, issues or commits. The proxy refuses to start when the variable is empty, and rotation means updating the environment plus registry and restarting the services.

Why does PotPlayer start instantly while Jellyfin Web sometimes buffers on the same file?

Jellyfin Web often remuxes or transcodes high-bitrate 4K REMUX files because of browser codec and subtitle limits, which costs CPU and adds buffering. PotPlayer direct-streams the original file over HTTP from the local TorBox proxy, so it seeks instantly with a full-cache bar and uses negligible server CPU while preserving the original video, audio and subtitle tracks.

How do resume and watched status stay in sync between PotPlayer and Jellyfin?

A lightweight tracker posts the playback position to the Jellyfin Sessions Playing Progress endpoint every five seconds while PotPlayer runs. When you pass eighty percent, it marks the episode Played, so Next-Up advances and other clients resume correctly. You can verify it live in the watch console, show-playback-log.ps1.

What should I do when the T drive looks stale or libraries are empty after a reboot?

Start the mounts before Jellyfin, because a scan that races a downed VFS indexes stub files and empty views. Verify the drive paths exist, refresh the rclone RC cache on ports 5572 and 5573, confirm proxy health on port 8888, then trigger a Jellyfin library refresh. The included check scripts return Nagios-style exit codes and JSON for fast automated checks.

What do I need installed, and which systems are supported?

Windows 10 or 11 x64 with PowerShell 7+, Jellyfin Server 10.x, PotPlayer x64 with the potplayer protocol registered, rclone with WinFsp and TorBox and Google Drive remotes, a TorBox API key, and Python 3.11 for the proxy, bridge and panel. Linux, macOS, Docker, Plex, Emby and remote hosting are not in scope. Google Drive sync is optional and TorBox is the primary cloud.

Is it safe to expose the panel or proxy to my local network?

No. Both bind to localhost with no login by design, so anyone on the network could control playback or services. Do not expose them without adding authentication and TLS. A Caddy or Cloudflared edge profile for secure remote access is on the roadmap, not part of the current release.

How do I install, update or remove it?

Clone the repository and run pwsh -File install.ps1, using -WhatIf first to preview every planned action. The guided alternative is setup-wizard.ps1. To update, stop the stack, pull the latest branch, re-run the installer and re-run the health checks. To remove it, run install.ps1 with -Uninstall. The full lifecycle is in docs/install.md.
